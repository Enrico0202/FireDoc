Automation API
Everything FireDoc exposes to scripts — three endpoints under /api/v1, plus the health probe.

The API mirrors the two web tools: upload a FortiGate config, get back the HTML report as a file (what you'd download from the web UI). Nothing is stored — every request is parsed in memory.

Authentication
All /api/v1/* endpoints require an API key.
  • X-API-Key header — set to the key configured in the API_KEY environment variable of the container. The health probe (/api/v1/health) is the only exception: it works without a key and reports whether a key is even configured.
  • Key missing server-side → every /api/v1 call returns 503 {"error": "API not configured"}.
  • Key wrong or absent in the request → 401 {"error": "Invalid or missing API key"}.
curl -s http://fortidoc:8080/api/v1/health
{
  "status": "ok",
  "version": "2.0.0",
  "api_configured": true
}
Endpoints
MethodPathReturnsWhat it does
GET /api/v1/health JSON Liveness + config probe. No key needed — api_configured tells you whether the API key is set server-side.
POST /api/v1/report HTML file Full audit report, downloaded as <hostname>_report_<YYYY-MM>.html (self-contained, works offline). Same content the web UI produces.
POST /api/v1/diff HTML file Config diff between two uploads, downloaded as <hostname_a>_diff_<YYYY-MM>.html.
POST /api/v1/diff/summary JSON Machine-readable twin of the diff — per-section change counts and the overall summary.
Report — POST /api/v1/report
One FortiGate export in, a downloadable HTML report out.
  • Content type — multipart/form-data, field name config.
  • Accepted files — .conf (native FortiGate export) and .yaml / .yml (converted to conf internally). Encrypted backups are rejected.
  • Success — 200 with the full HTML document, Content-Disposition: attachment.
# HTML report (opens in a browser, self-contained)
# @ before the path = upload the file — without the @, curl sends the path as a string and the API answers 400 "No file selected"
curl -X POST http://fortidoc:8080/api/v1/report \
     -H "X-API-Key: $FORDOC_KEY" \
     -F "config=@/path/to/fortigate.conf" \
     --output report.html
Diff — POST /api/v1/diff
Two FortiGate exports in, a downloadable diff report out.
  • Content type — multipart/form-data, two fields: config_a (before) and config_b (after). Both required.
  • Accepted files — same as the report endpoint.
  • Success — 200 with the diff report HTML, named after config_a's hostname.
# HTML diff report
# @ before each path = upload the file — without the @, curl sends the path as a string and the API answers 400
curl -X POST http://fortidoc:8080/api/v1/diff \
     -H "X-API-Key: $FORDOC_KEY" \
     -F "config_a=@/path/to/before.conf" \
     -F "config_b=@/path/to/after.conf" \
     --output diff.html

# JSON summary instead
curl -X POST http://fortidoc:8080/api/v1/diff/summary \
     -H "X-API-Key: $FORDOC_KEY" \
     -F "config_a=@/path/to/before.conf" \
     -F "config_b=@/path/to/after.conf"

Error handling
200 report / diff 400 missing file, missing field, or empty upload 401 invalid or missing X-API-Key 415 unsupported or encrypted file 422 file readable but config failed to parse 503 API key not configured on the server 
{
  "error": "Invalid or missing API key"
}

All errors are JSON: {"error": "<message>"} with a matching status code. Check the health endpoint first — if api_configured is false, every other call will 503 until the key is set.
